Esta área explica como o Lumora funciona por dentro. O objetivo é que você entenda a arquitetura antes de abrir o código, e saiba onde olhar quando abrir.

O código-fonte fica no repositório `lumora`, um monorepo pnpm. Esta documentação fica no repositório `lumora-docs`.

## Como esta documentação se relaciona com o código

- O **código** explica como algo foi implementado.
- Esta **documentação** explica como o sistema funciona: responsabilidades, fluxos, garantias e limites.
- Os **ADRs** explicam por que uma decisão arquitetural foi tomada.

Quando esta documentação e o código divergirem, o código prevalece. Corrija a página.

<Warning>
  O `README.md` do repositório `lumora` descreve em parte a arquitetura pretendida, e não só a implementada. Ele cita, por exemplo, três buckets, capacidade provisionada no DynamoDB, ambientes `dev` e `prod`, funções de pagamento e segredos no SSM, que não existem no código atual. Esta documentação descreve o estado implementado. As diferenças conhecidas estão em [Limitações e pontos futuros](/developers/limitations#divergências-entre-o-readme-e-o-código).
</Warning>

## Mapa do repositório `lumora`

| Caminho | Conteúdo |
| --- | --- |
| `apps/web` | Frontend React (Vite). Área do fotógrafo em `/app/*` e área do cliente em `/g/:token/*`. |
| `services/api` | Código das sete funções Lambda: handlers, controllers, casos de uso, domínio e infraestrutura. |
| `packages/contracts` | Schemas zod dos contratos HTTP, consumidos pelo frontend. O backend mantém uma cópia. |
| `infra/template.yaml` | Toda a infraestrutura AWS, em AWS SAM. |
| `infra/layers/sharp` | Layer com o binário nativo do sharp para Lambda arm64. |
| `tests` | Testes de paridade dos contratos, de paridade do cálculo de preço e do template SAM. |
| `scripts` | DynamoDB Local, criação de usuário de teste e API simulada da área do cliente. |
| `docs` | Notas internas: design system, guia de integridade, revisões e medições pontuais. |

## Convenções desta documentação

- Identificadores do código aparecem em inglês e sem tradução, como `PENDING_UPLOAD` e `processingAttemptId`.
- Caminhos de arquivo são relativos à raiz do repositório `lumora`. Dentro de `services/api`, os caminhos são relativos a `src`.
- "Atualmente" e "hoje" marcam comportamento implementado. "Consideração futura" e "planejado" marcam o que ainda não existe.
- Exemplos de chaves e identificadores são fictícios.
